# POCKET CIRCUIT / Kart Racer

個性の違う 20 コースを、最大 8 台で走るオリジナルの 3D カートレース。1 人用（プレイヤー + CPU 7 台）と、オンライン対戦（最大 8 人、空いた枠は CPU）で、1〜3 周の順位とタイムを競います（既定 3 周）。モデル・景色は手続き生成、音は WebAudio 合成で、外部画像・モデル・音声ファイルは使いません。

▶ **今すぐ遊ぶ: https://machaniconico.github.io/kart-racer/** （PC・スマホ対応。スマホは横画面で）

## 起動と開発

Node.js **22.12 以降**（22 LTS 推奨）を使用してください。

```sh
npm install
npm run dev
```

表示されたローカル URL の `/kart-racer/` を開きます。スマホからは同じ Wi-Fi に接続し、Vite の Network URL に `/kart-racer/` を付けてアクセスしてください。

```sh
npm run build       # strict TypeScript チェック + dist/ に本番ビルド
npm test            # Vitest を一度実行
npm run test:watch  # Vitest の監視実行
npm run typecheck   # 型チェックのみ
npm run preview    # ビルド済み dist/ を確認
npm run e2e         # E2E（Playwright。オンライン対戦と 20 コース。下記）
```

`npm run e2e` は `e2e/multiplayer.spec.ts` と `e2e/courses.spec.ts` を順に実行します。`courses.spec.ts`・`courses-m10.spec.ts`・`courses-m11.spec.ts` は 20 コースそれぞれで選択から 3 周の完走、コース別ベスト、描画負荷を確認します。`courses-m11.spec.ts` は加えて CHASM LEAP の落下リスポーン（黒画面なし、2 秒以内に操作復帰）と EXTREME CUP（5 カップ目）の 4 レースを確認します。`multiplayer.spec.ts` は 2 つのブラウザコンテキストで実際にルームを作って参加します。**公開の PeerJS ブローカー**を使うため、ブローカーの状態や回線によって不安定な場合があります。CI（`.github/workflows/e2e.yml`）では手動実行（`workflow_dispatch`）のみです。初回は `npx playwright install chromium` が必要です。

**視覚テスト（スクリーンショットの golden）**: `courses.spec.ts` の画面比較は platform ごとのディレクトリ（`e2e/__screenshots__/darwin/` に 27 枚）の golden と照合します。その platform の golden が無ければ `golden-skipped` の注釈を付けて比較だけを省き、他の検査は実行します（Linux は golden を追加するまでこの扱い）。閾値は `threshold 0.2`、`maxDiffPixels 0` です。描画負荷の drawCalls / triangles は platform を問わず完全一致を見ます。

Linux の golden の取り方: GitHub の Actions で「Capture linux goldens」（`.github/workflows/goldens-linux.yml`、手動実行のみ）を実行します。書き出した直後に同じ runner で再照合し、通れば artifact `linux-goldens` ができるので、中身を `e2e/__screenshots__/linux/` に置いてコミットします。以後は Linux でも自動で照合されます。再照合が通らなければコミットしません。golden を意図して作り直すときだけ `KART_GOLDENS=write npx playwright test e2e/courses.spec.ts --update-snapshots` を使います。

## 遊び方

### 3 つのモード（1 人用）

タイトルのモード行で選びます。

- **レース**: 従来どおり、プレイヤー 1 台と CPU 7 台で、選んだコースを走ります。
- **グランプリ**: カップ 5 つ（SUNRISE CUP = 01〜04、HORIZON CUP = 05〜08、ZENITH CUP = 09〜12、ECLIPSE CUP = 13〜16、EXTREME CUP = 17〜20）の 4 コースを続けて走り、順位ごとの得点（1 位から 10・8・6・5・4・3・2・1 点）の合計で競います。レースの合間に順位表が出て、最後に表彰台が出ます。総合の同点は、直近のレースの順位、次に車の番号の小さい順で決まります。進行は保存せず、再読み込みで最初からになります。オフライン専用です。
- **タイムアタック**: 自分 1 台だけ、アイテムボックスなしで走ります。このコースと周回数で一番速い走りは「ゴースト」（半透明のカート）として次の走行に一緒に走り、ミニマップには出ません。ゴールタイムが速ければゴーストを更新し、ベストラップも別に残ります。10 分を超える走行は残りません。

### CPU の強さ

「やさしい / ふつう / つよい」から選びます（初期値はふつう）。レースとグランプリで効き、タイムアタックには CPU がいません。やさしいは速度が約 7% 低く、つよいは約 4% 高くなります（コースごとの周回時間は、MEADOW でやさしい 約 73.0 秒・つよい 約 66.6 秒、ふつう 約 68.5 秒）。**オンラインの部屋は常にふつうの CPU です。**

MOSSWOOD TRAIL（森のコース）の CPU は走行ラインを持ち、ヘアピンでは外から入ってイン側に付き、左カーブはイン寄り、S 字は浅く抜けます。人間のカートの挙動やベストタイムは変わりません。

### 1 人用のコースと周回数

タイトルのコース選択（番号 01〜20 の 44×44 px のボタン。PC は 8 個ずつ 3 段（8・8・4）、縦画面のスマホは 5 つずつ 4 段）と、その下の周回数（1 / 2 / 3、既定 3 周）を選び、「レースをはじめる」で 3・2・1 の後にスタート。プレイヤー 1 台と CPU 7 台で走ります。道路の外の芝は減速し、壁や他のカートに衝突すると速度や進路が変わります。チェックポイントを順番に通過して、選んだ周回数を走ってください。ベストタイムは周回数ごとに別々に残ります（以前の記録は 3 周として引き継がれます）。逆走・チェックポイントの飛ばし・コースの瞬間移動では周回が成立しません。

### オンライン（最大 8 人）

1. **ホスト**: 「オンライン対戦」で「ルーム作成」を押し、表示されたルームコードを参加者に共有する（コピー / 共有ボタン）。
2. **ゲスト**: 「ルームコード」欄にコードを入れて参加する。
3. ロビーで名前（10 文字まで）とカートの色を選ぶ。コースと周回数（1〜3 周、既定 3 周）はホストがロビーで選び、ゲストには読み取り専用で表示される。
4. ホストが「スタート」を押すとレースが始まる。人数が 8 に満たない枠は CPU が走ります。

通信プロトコルは **v19** です。オンライン対戦は、ホストもゲストも同じ版（v19）のページである必要があります。旧ページ（v18 以前）とは別ルームになるため、全員が新しいページを開いてください。

回線が悪いと、他のプレイヤーのカートの表示が最大 250 ms 遅れることがあります（自分のカートは遅れません）。

### 近道と落とし穴

SUNSCAR CANYON の終盤には、道が島で 2 本に分かれる区間があります。

- **外側のレーン**: 舗装されていて安全。ただし遠回り。
- **内側のレーン**: 近道。ダートの上にあるブーストを踏んで加速し、ジャンプ台で飛んで、先にある落とし穴を越える。成功すると外側より約 0.5 秒速い。
- ブーストを踏み外すと穴に落ちて、ほぼ止まって spin します。外側より約 1.75 秒遅くなるので、自信がなければ外側へ。

CPU もこの 2 本のレーンを使い分けます（約 3 周に 1 回、近道を選びます）。

ベストタイムはコース・周回数別に保存します。以前の MEADOW LOOP の記録は引き継がれます。ただし 4 コースとも横幅を約 30% 広げた（レイアウトが変わった）ため、それ以前のベストタイムは表示されず、リセットされます。

### 動く障害物・ゲート・回転床（NEON NIGHTLINE）

- **動く障害物**: 左右に揺れる柱と、開いたり閉じたりするゲートがあります。動きは一定のリズムなので、通れる間に抜けるか、空いている側へ避けてください。CPU も避けて走ります。
- **回転床**: 円形の床の上では車体がゆっくり回されます（地上のみ。位置は動きません）。ハンドルで向きを立て直してください。
- **ベストタイム**: コースが変わったため、NEON NIGHTLINE のベストタイムだけがリセットされます。他の 3 コースは引き継がれます。
- **オンライン対戦**: 通信の版が上がったため、ホストもゲストも新しいページを開く必要があります（古いページとは同じ部屋に入れません）。

### 起伏とバンク（FROSTBITE PEAK）

- **起伏**: FROSTBITE PEAK に最大 19 m ほどの高低差と、きつめの上り坂（勾配 約 20%）ができました。上りでは最高速と加速が落ち、下りでは最高速と加速が増えます（アクセルを離すかブレーキ中は、下りで勝手に加速します。止まっている間は転がりません）。
- **バンク**: 最初の氷のスイーパー（30〜85 m 付近）が傾いています。傾きの低い側へ曲がると少し旋回しやすくなります。車体も道路の傾きに合わせて傾きます。
- **ベストタイム**: コースが変わったため、FROSTBITE PEAK のベストタイムだけがリセットされます。他の 3 コースは引き継がれます。
- **オンライン対戦**: 通信の版が上がったため、ホストもゲストも新しいページを開く必要があります（古いページとは同じ部屋に入れません）。

### つながらないとき

接続は P2P（ブラウザ同士の直接通信）です。一部の会社や学校のネットワーク、モバイル回線では、直接つながらないことがあります。**同じ Wi-Fi か、別の回線**で試してください。通信は PeerJS の既定設定で、PeerJS 既定の公開 STUN/TURN サーバを利用します（無償の公開サービスなので可用性は保証されません）。それでもつながらない環境があります。

### 制約

- **ホストは画面を閉じたり、アプリを切り替えたりしないでください。** ホストの画面が止まると全員のレースが止まります。iOS でホストが画面を離れて通信が止まると、次のどちらかで切断されます。ICE が `disconnected` の状態が 8 秒続いたとき。レース中にホストからのスナップショットが 5 秒止まったとき（ゲストはホスト喪失として扱います）。
- ホスト移譲、観戦、途中参加はありません。

### 操作

| 操作 | PC | スマホ | 標準ゲームパッド |
| --- | --- | --- | --- |
| ステア | ← → / A D | 左スティックを左右へ | 左スティック / 十字キー |
| アクセル | ↑ / W | アクセル、または左スティック上の「自動アクセル」切替 | A / RT |
| ブレーキ | ↓ / S | ブレーキ | B / LT |
| ドリフト・ホップ | Space を押しながら曲がる | 「ドリフト」を押しながら曲がる | X |
| アイテム | Shift / E | ITEM | RB / Y |
| 一時停止（1 人用のみ。オンラインでは退出の確認だけで、レースは止まらない） | Esc / 一時停止ボタン | 一時停止ボタン | 画面の一時停止ボタン |

**ステア感度（スマホのみ）**: タイトル画面と一時停止画面の「ステア感度」スライダー（1〜5、初期値 3）で、左スティックの効き方を変えます。1 が最もゆるやかで、5 は入力どおり（線形）です。値はブラウザに保存され、再読み込みしても残ります。

**ハンドルアシスト**: タイトル画面と一時停止画面のスイッチで切り替えます。コースの先を見て、壁に寄りすぎないようにステアを少し補正します。初期値は、スマホ（タッチ）が ON、キーボード・ゲームパッドが OFF です。自分でステアを大きく切っているときは補正が弱まり、逆向きには押しません。設定は保存されます。

**ドリフトの曲がり方**: ドリフト中は、ステアを切らなくてもドリフトの向きに曲がり続け、ステアで曲がりの大きさを調整できます。内側に切ると小さく、外側に切るとゆるやかに回ります（外側いっぱいに切っても、始めたドリフトの向きは反転しません）。

ドリフトの火花が **水色（0.65 秒）→ オレンジ（1.5 秒）** に変化します。ドリフトを離すと、溜めた段階に応じてミニターボが発動します。

アイテム（トラップ・ボルト・ダミーボックス・ポップボム）は、ボタンを**押しっぱなしにすると後ろに構えて防御**し、**離すと発射**します。構えている間は、後ろから来たボルト・ボムを防げます（防ぐとアイテムを消費）。ダッシュ系・オーラ・ストーム・インクは押した瞬間に発動します。

### アイテム

アイテムボックスはコース上の 8 列・計 24 個。取得すると 5 秒で復活します。一度に持てるアイテムは 1 個で、順位によって出やすいものが変わります（上位は設置・基本系、下位は強力な加速・無敵系）。

ボックスを取ると、アイテムがスロットのように約 1.4 秒回って決まります。回っている間はアイテムを使えません。回り始めて 0.3 秒たった後にボタンを押すと、その場で止められます（早止め。押しっぱなしにしても、いったん離すまでアイテムは使われません）。

| ポップボム | 前方（ブレーキを押しながらで後方）へ投げ、2.5 秒または接近で爆発。半径 4.5m をスピンさせる（自分も含む）。 |
| ロケットライド | 4 秒間、自動運転で最高速 ×1.5、被弾無効、触れた相手をスピンさせる。 |
| オービットガード | 自分の周りを 3 個のトラップまたはボルトが周回し、触れた相手をスピンさせる（1 個消費）。使用で 1 個を前方に発射または後方に設置。 |

スマホは横画面推奨。ステアとドリフトなどの同時押しに対応し、タッチ端末では自動アクセルが初期 ON です。1 人用では、画面を離れた場合に自動で一時停止します（オンラインでは止まりません）。音は開始操作後に有効になり、右上のボタンでミュートできます。

`localStorage` に保存するのは、ミュート設定、ステア感度、ハンドルアシスト、CPU の強さ、1 人用レースのコース別・周回数別ベストの合計タイム（オンラインでは更新しません）、タイムアタックのゴーストとコース別ベストラップです。グランプリの進行は保存しません。ストレージが利用できない場合もプレイできます。1 人用ではプレイヤーがゴールすると結果画面に移ります。オンラインでは自車がゴールしてもすぐには移らず、人間全員のゴールかタイムアウトを待ちます。結果画面では、未完走の車をその時点の進行順位で「走行中」と表示します（タイムアウトで終わった場合は「DNF · 未完走」）。

## 構成

```text
src/
  sim/        # three / DOM に依存しない固定 60 Hz のシミュレーション
    types.ts  # InputFrame、InputSource、JSON 保存可能な RaceState
    track.ts  # 閉じた Catmull-Rom スプライン、距離・路面投影
    race.ts   # 簡易物理、衝突、ドリフト、アイテム、レース進行
    laps.ts   # 方向付きチェックポイント、周回、順位
    ai.ts     # CPU の InputFrame 生成
    random.ts # seed 付き PRNG
    itemTable.ts # 順位別のアイテム抽選テーブル（8 位まで）
    sim.test.ts
    surfaces.ts # 路面特性（ice / boost / jump）
    tracks/   # 20 コースの定義（meadow / canyon / snowpeak / neon / harbor / forest / volcano / skyline / dunes / garden / speedway / bayou / cavern / temple / serpentine / lunar / summit / chasm / velodrome / spire）と登録
  render/     # three のカート、追従カメラ、火花。course/ はコースごとのテーマと路面の描画
  input/      # キーボード・タッチ・Gamepad を InputFrame に変換
  audio/      # WebAudio のエンジン・ドリフト・効果音
  net/        # オンライン対戦: Transport 抽象、ホスト/ゲストのセッション、スナップショット codec、予測・補間、PeerJS 実装、ルームコード
  ui/         # タイトル、HUD、ミニマップ、結果、一時停止、LobbyUI（ルーム作成・参加・ロビー）、アイテムアイコン
  main.ts     # 固定ステップ実行、状態補間、各層の接続
  storage.ts  # 例外処理付きのベストタイム・ミュート保存
  style.css
.github/workflows/
  deploy.yml  # main への push で Pages に公開
  e2e.yml     # オンライン対戦 E2E（手動実行のみ）
e2e/          # Playwright。multiplayer.spec.ts（実 PeerJS ブローカー）と courses.spec.ts・courses-m10.spec.ts・courses-m11.spec.ts（20 コースの選択と 3 周、落下リスポーン、EXTREME CUP）
```

シミュレーションは `stepRace(state, inputs)` で 1 tick 進みます。`RaceState` に RNG 状態を含むため、同じ seed と tick ごとの `InputFrame[]` で再現できます。`JSON.parse(JSON.stringify(state))` したスナップショットからも継続可能です。CPU も入力を作るだけで、物理を直接上書きしません。ネットワーク入力もこの境界で差し替わります。

描画は前後のカート状態を補間し、シミュレーションを変更しません。木・岩・縁石・ガードレールなどはインスタンシング、カート本体はマテリアルごとに結合しています。影は directional light 1 灯、DPR は最大 2。`prefers-reduced-motion` 時はタイトルカメラの揺れや追従カメラのドリフト演出を抑えます。

開発サーバーでのみ `window.__kartDebug` から状態の参照と `advance(ticks, true)` による CPU 自動走行検証ができます。本番ビルドには含まれません。

## GitHub Pages

`vite.config.ts` の `base` は **`/kart-racer/`** です。GitHub リポジトリの Settings → Pages → Source を **GitHub Actions** に設定してください。`main` への push または workflow の手動実行で、`npm ci` → テスト → ビルド → `actions/deploy-pages` の順に公開します。リポジトリ名を変える場合は `base` も変更してください。

## 実装上の範囲

- コースは 20 本（MEADOW LOOP / SUNSCAR CANYON / FROSTBITE PEAK / NEON NIGHTLINE / TIDEWATER HARBOR / MOSSWOOD TRAIL / EMBER CALDERA / STRATOS CITY / SIROCCO DUNES / BLOSSOM GARDEN / THUNDER OVAL / MOONLIT BAYOU / CRYSTAL HOLLOW / SUNKEN TEMPLE / SERPENT PASS / LUNAR BASIN / SUMMIT DROP / CHASM LEAP / WALL BOWL / SKY SPIRE）。1 人用（CPU 戦）とオンライン対戦（最大 8 人、P2P、ホスト権威）。通信は PeerJS 既定の公開 STUN/TURN を利用します。
- 物理は平面上の簡易カート物理と路面の高さへの追従です。ホップは描画演出で、立体ジャンプや転倒は扱いません。
- 60fps は中級スマホでの目安です。実機・ブラウザ・電力設定によって性能とゲームパッドの割り当ては異なります。
- WebGL が利用できない場合は画面内に再読み込み案内を表示します。音声が許可されない場合もゲームは動作します。
